# Архитектура

| Файл | Ответственность |
| --- | --- |
| `src/main.rs` | Настройки, общее состояние, цикл синхронизации, HTTP-просмотр |
| `src/caldav.rs` | REPORT, VEVENT/VTODO, часовые пояса и метаданные ресурсов |
| `src/task_sync.rs` | Устойчивая очередь, слияние статуса выполнения и PUT |
| `src/render.rs` | Сетка месяца, правая панель, SVG и растеризация |
| `src/todo.rs` | Действия, отметки, страницы и таймер возврата |
| `src/energy.rs` | Различия изображений, прямоугольники, bitmap и диагностика |
| `src/native.rs` | InkView, очередь ввода, e-ink, Wi-Fi и сон |
| `src/preview.html` | Веб-просмотр того же изображения и областей нажатия |

## Синхронизация

Для VEVENT запрашивается окно месячной сетки с `calendar-data/expand`, для VTODO — задачи коллекции, включая выполненные. Они нужны для отметок в календаре и отмены выполнения.

Локальное действие сохраняется до сетевого запроса. Несколько быстрых переключений объединяются в последнее желаемое состояние задачи. Касания и кнопки не теряются, если общее состояние временно занято.

Порядок записи:

1. Прочитать актуальный ресурс VTODO и сильный ETag.
2. Проверить UID и принадлежность ресурса выбранной коллекции и серверу.
3. Сохранить исходный VCALENDAR, заменив только метаданные выполнения нужного VTODO.
4. Отправить PUT с `If-Match`.
5. При 412 перечитать ресурс и повторить слияние, до трёх попыток.
6. Удалить подтверждённое изменение из очереди, только если пользователь не изменил его во время запроса.

Неизвестные свойства, переносы строк, заметки, сроки и VALARM сохраняются. Без сети или подтверждения очередь остаётся на накопителе. Новый ресурс вместо исчезнувшей задачи не создаётся автоматически.

До подтверждения локальная очередь имеет приоритет над прочитанным серверным статусом. Старые локальные галочки предыдущих версий однократно переносятся в очередь после успешного чтения сервера.

Стандарты: [CalDAV / RFC 4791](https://www.rfc-editor.org/rfc/rfc4791.html), [iCalendar / RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html).

## Экран

SVG сравнивается до растеризации. После растеризации сравниваются пиксели; изменившиеся плитки объединяются в ограниченное число прямоугольников.

InkView рисует 8-битные изображения из памяти. Для частичных обновлений подготавливаются только нужные области. При выключенном веб-просмотре промежуточные PNG/SVG не записываются. Шрифты переиспользуются в пределах процесса.

Полная очистка требуется при первом показе, возвращении из другого приложения и после накопления определённого числа или площади частичных обновлений. Повторный сигнал SHOW после обычного пробуждения сам по себе не требует полной перерисовки.

## Хранение

| Файл в каталоге кэша | Содержимое |
| --- | --- |
| `events.json` | События и время последней успешной синхронизации |
| `completed-tasks.json` | Отметки выполнения |
| `task-outbox.json` | Неотправленные или неподтверждённые изменения VTODO |
| `power-status.json` | Диагностика обновлений, сна и длительности обработки |
| `calendar.png`, `calendar.svg` | Изображение для веб-просмотра, если он включён |

Файлы заменяются через временный файл и переименование. Кэш содержит личные данные и исключён из Git. Пароль хранится отдельно от JSON-конфига и передаётся через переменные окружения.

## Проверенная граница

Модульные и локальные интеграционные тесты проверяют данные и состояния. ARM-сборка проверялась в эмуляции с заглушкой InkView. Реальный экран проверялся на PB740-2; эмуляция не измеряет задержку физической панели и расход аккумулятора. Результаты нельзя переносить на все модели PocketBook без проверки.
